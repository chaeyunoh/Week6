# 6주차 과제 2 — Mock 분류기 확장

## 실행 결과 (리뷰 36건, captures/task2_pipeline_v2.png)

- 처리 {처리}건 / 실패 {실패}건 (전체 36건)
- 불량 응답 {N}건: 코드펜스 {a}건 / 사족 {b}건 / 잘림 {c}건
- 복구 {복구}건 / 실패 {실패}건

## 실패가 불량 응답보다 적은 이유

불량 응답 {N}건 중 코드펜스형과 사족형 {a+b}건은 방어 코드가 복구하여 정상 처리했고, 잘린 JSON형 {c}건만 실패로 집계되었다. 따라서 실패 건수({실패}건)는 불량 응답 건수({N}건)보다 적으며 잘림 건수와 같다.

## 방어 코드별 처리

| 불량 유형 | 처리 방어 | 결과 |
|---|---|---|
| 코드펜스 | 방어 1 (``` 제거) | 복구 |
| 사족 | 방어 1-2 (첫 `{`부터 마지막 `}`까지 추출) | 복구 |
| 잘림 | 방어 0 (`stop_reason == "max_tokens"` 확인) | 실패 |

사족 복구를 적용하지 않았다면 이 실행의 실패는 {b+c}건(사족 {b} + 잘림 {c})이었고, 적용 후 {c}건으로 {b}건 줄었다.

## 잘린 JSON을 복구할 수 없는 이유

잘린 응답은 일부 필드와 닫는 중괄호가 응답 자체에 없다. 예를 들어 `{"category": "배송", "sen`에는 sentiment와 score 값이 존재하지 않으므로, 추출해도 파싱할 수 없고 값을 추측해 채우면 잘못된 데이터가 된다. 그래서 `stop_reason`으로 잘림을 먼저 감지해 실패로 집계한다.
